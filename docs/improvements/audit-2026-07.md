# Audit post-migration — TalkControl v0.5.0 (juillet 2026)

Audit réalisé après la migration Node 24 / TypeScript strict / Vite / Vitest (v0.5.0, étapes 0–18 de `docs/migration/`).
Cinq axes analysés : dépendances, patterns de code, tests, sécurité/performance, DX/CI — plus un axe **agentic**.

**Verdict global** : la migration a assaini la syntaxe (0 `@ts-ignore`, 0 `eslint-disable`, 0 `var`, strict activé)
mais les dettes restantes sont **architecturales** : sécurité de type en trompe-l'œil, Redux surdimensionné,
CSS dupliqué ×13, e2e factices, et surfaces de sécurité ouvertes alors que l'app s'expose via ngrok.

---

## 1. Sécurité — le point le plus grave

L'application expose **trois services CORS `*` sur Internet via ngrok** pendant chaque présentation.

| # | Constat | Localisation | Gravité |
|---|---|---|---|
| S1 | **SSRF ouvert** : la cible du proxy est pilotée par le cookie non signé `tc-presentation-url`, sans allowlist ni blocage IP privées/metadata, avec `secure: false`. Le patcher `fetch()` la même URL depuis un query param. | `src/server/controllers/proxy.controller.ts:10-20`, `patcher.controller.ts:12,22` | **Critique** |
| S2 | **Aucune auth socket.io** : pas de middleware, pas de room, pas de token. Quiconque a l'URL ngrok pilote la présentation (`inputEvent`, `init` réécrit le store, events plugin re-broadcastés sans validation). | `event-bus-websockets-server.ts:12-58`, `tc-server.ts:18-27` | **Critique** |
| S3 | CORS `*` sur Express, socket.io et Vite dev server, tous tunnelés ngrok. | `router.ts:9`, `event-bus-websockets-server.ts:12`, `vite.config.mts:120-126` | Haute |
| S4 | Cookie `tc-presentation-url` posé sans `httpOnly`/`secure`/`sameSite`, cookie-parser sans secret. | `patcher.controller.ts:34`, `router.ts:10` | Haute |
| S5 | **Token ngrok dans un fichier versionné** `config/config.json`, réécrit au runtime (URLs tunnels) → risque de commit du secret. Pas de `.env`, pas de fichier example. | `config/config.json`, `src/environment/services/{tunnel,config-file}.ts` | Haute |
| S6 | `innerHTML` non assaini sur du contenu venant de la présentation distante. | `notes.ts:22`, `touch-pointer/index.ts:100` | Moyenne |
| S7 | Vuln npm : esbuild ≤0.24.2 (moderate) via vite ≤6.4.2 et vitepress ≤1.6.4. Fix = Vite 7+/8. | `npm audit` | Moyenne |

**Préconisation forte** : traiter S1–S5 avant toute autre modernisation (étapes 03–05 du plan).
Un outil de présentation qui se tunnelise volontairement sur Internet ne peut pas rester sans pairing ni validation de cible.

## 2. Tests — la couverture affichée ne protège pas

| # | Constat |
|---|---|
| T1 | **Les 24 tests e2e Playwright valident une maquette statique** (`e2e/fixtures/index.html`, chargée en `file://`, `webServer: null`). **0 des 10 scénarios du golden-path** n'est couvert bout-en-bout. La suite donne une fausse impression de sécurité. |
| T2 | Marges de coverage quasi nulles : statements/lines 70.55 % pour un seuil de 70 %. `coverage-final.md` décrit encore l'outillage c8 disparu — chiffres non reproductibles. |
| T3 | Gaps structurels : tous les wrappers `*-tc-component.ts`, `plugins/plugin.ts`, `server/{bootstrap,index}.ts`, `common/event-bus/{event-bus-component,event-bus-proxy}.ts`, `common/services/config.ts`, tout `environment/` et `compat/`. 7 web components en smoke-only (`shadowRoot not null`). |
| T4 | Zones molles réelles : `server` 54 % stmts, `client/tc-component` 49 %. |
| T5 | Fragilités : accès à l'état privé via `(el as any)`, singleton touch-pointer réinitialisé à la main, setup dupliqué (montage LitElement, `document.body.innerHTML = ''`). |

**Préconisation forte** : les e2e réels sur l'app (golden-path scripté) sont le **prérequis n°1** du plan —
c'est le filet qui rend toutes les autres étapes iso-fonctionnelles vérifiables (étape 01).

## 3. Dépendances

Aucune dépendance totalement morte (knip ne signale que `http-server` et `reveal.js`, faux positifs : utilisés via scripts npm).
Mais plusieurs sont **remplaçables ou en retard** :

| Package | État | Préconisation |
|---|---|---|
| `colors` 1.4 | 1 seul usage (`get-started.ts`), package saboté en 2022 (incident supply-chain) | **Supprimer** → `styleText` natif de `node:util` (Node 20.12+) |
| `redux` 4 + `redux-logger` + `redux-mock-store` | 1 store, 1 reducer, 2 actions, 1 abonné. Pub/sub déguisé. `redux-logger` gated off par défaut, sans typings | **Supprimer les 3** → store minimal typé maison (~40 lignes) |
| `lit-element` 4 seul | API pré-décorateurs (`static get properties()`), `lit-html` importé en dep fantôme transitive | **Migrer vers `lit`** + décorateurs |
| `bulma` 0.9.0 | 2 majeures de retard (1.0.4), et importé **deux fois** (CSS global 196K + `?raw` dans 13 shadow roots) | Dédupliquer puis upgrader |
| `vite` 5.4 | 3 majeures de retard (8.1), porte la vuln esbuild | **Upgrader** (fixe l'audit) |
| `vitepress` 1.6 | dépend du vite vulnérable | Upgrader avec Vite |
| `eslint` 9 / `@eslint/js` / `globals` 15 / `eslint-config-prettier` 9 | ESLint 10 dispo | Upgrader groupé |
| `supertest` 6.3 | v7 dispo | Upgrade simple |
| `query-selector-shadow-dom` 0.3 | v1.0 dispo | Upgrade simple |
| `typescript` 5.9 | TS 7 (compilateur Go, ~10× plus rapide) dispo | Optionnel, à évaluer en fin de plan |
| Champ `browser: {"socket.io": false}` | Vestige webpack, redondant avec l'alias Vite → stub | Supprimer |
| Override `y18n ^4.0.1` | Tiré par `qrcode`→`yargs@15`. Toujours pertinent tant que qrcode 1.5 est là | Garder, documenter |
| `--legacy-peer-deps` en CI | Cache un conflit de peers non résolu | Résoudre à l'upgrade Vite |

## 4. Patterns de code

Codebase compacte (60 fichiers, 2642 lignes src/) — les problèmes sont concentrés :

| # | Constat | Localisation |
|---|---|---|
| P1 | **Sécurité de type illusoire** : le bus d'événements est typé `unknown`, tout le risque est reporté sur ~30 casts `as X` et ~64 `!`. `as unknown as string` dans `event-bus-resolver.ts:33`. | event-bus + tous les consommateurs |
| P2 | **~40 lignes dupliquées** : `handleInput` / `handleTouch` quasi identiques. `handleTouch` n'est d'ailleurs **jamais câblé** dans `TCServer.init` (code mort probable). | `revealjs-server-engine.ts:10-84` |
| P3 | Bulma complet injecté dans le shadow DOM de **13 composants** (~200K × 13 en mémoire, gonfle le bundle principal à 308K). | `compat/lit-styles-compat.ts` + 13 composants |
| P4 | Plugin loader verrouillé par un `switch` codé en dur — ajouter un plugin = éditer 2 endroits. | `plugin-loader.ts:7-18` |
| P5 | Singletons partout : `export const instance` (plugins), services en `export default {}`, `config` importé du JSON. Complique le test et le multi-présentation. | plugins, services |
| P6 | Patterns datés : `.then()` au cœur, `.bind(this)`, `which`/`keyCode` dépréciés, event `keypressed` **non-standard donc jamais déclenché** (bug dormant), `console.*` brut (15×) au lieu du service logger. | `url-form.ts:19-20`, `keyboard/index.ts:12`, divers |
| P7 | Duplication UI : `formatTime()` copié dans clock+timer, mécanique dropdown copiée dans les 2 menus, wrappers TCComponent quasi identiques. | web-components |

## 6. Agentic — inexistant dans le repo

Le repo n'a **aucune configuration agentic versionnée** : pas de `CLAUDE.md`, pas de `.claude/settings.json` partagé,
pas de skills/agents/hooks/commands. Le seul artefact est un `settings.local.json` pollué de permissions mortes (Mocha, PIDs).
Or le projet est développé quasi exclusivement avec des agents (la migration entière l'a prouvé).

**Préconisation forte** : versionner le socle agentic (étape 17) — contexte projet, commandes de validation,
protocole d'exécution d'étapes, revue de code automatisée. C'est ce qui garantit la qualité des contributions IA futures.

---

## Préconisations fortes — résumé

1. **Filet d'abord** : e2e réels sur les 10 scénarios golden-path avant tout refactor (étape 01).
2. **Sécurité avant modernisation** : anti-SSRF, pairing socket, secrets hors git (étapes 03–05).
3. **Supprimer plutôt qu'upgrader** quand l'état de l'art le permet : `colors`→natif, `redux`→store maison, `lit-element`→`lit`.
4. **Une seule source CSS** : Bulma partagé via `adoptedStyleSheets`, puis Bulma 1.x.
5. **Typer le bus d'événements** : c'est la clé de voûte — élimine les ~30 casts et rend les refactors sûrs.
6. **CI qui protège vraiment** : lint bloquant, caches, coverage gate avec marges reconstituées.
7. **Socle agentic versionné** : CLAUDE.md + skills de vérification + revue automatisée.

Le plan d'exécution détaillé est dans [README.md](README.md) (17 étapes, exécutables par un modèle Sonnet).
